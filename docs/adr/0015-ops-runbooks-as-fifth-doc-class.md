# ADR-0015: 运维手册作为第五类文档,就地更新

- 状态: 已接受(2026-07-27)

## 背景与问题

清理旧设计文档时发现:`docs/` 下有一批文档既非决策、非术语、非施工文档、也非踩坑复盘——`mac-signing.md`(证书导出与 Secrets 语义)、`dmg-notarization-pipeline.md`(逐 DMG 验证命令与失败判读)、`pages-deploy-guide.md`(Pages 的 Root directory 等配置真相)、`download-statistics.md`(统计口径定义 + Token/CORS 配置)、`r2-setup-guide.md`(R2 凭据与最小权限)。

它们描述**当前仍在执行的流程如何操作**,是换机/换证书/重建 Pages/排查发布失败时唯一可查处;ADR-0012 只记"为什么 fail-closed",不含任何命令。ADR-0013 的四分类装不下它们,按"旧设计文档"处理会误删。

## 备选项

1. **新增第五类「运维手册」**,持久保留、随流程变更**就地更新**
2. 塞进"复盘"类——否决:复盘是历史叙事(只追加、记录当时如何排查),手册是现行操作说明(必须与当前流程一致,过时即有害),生命周期相反
3. 塞进 ADR——否决:ADR 只追加不改写,而手册必须随流程改写;且 ADR 记 why,手册记 how
4. 移出仓库(wiki/密码管理器)——否决:与代码同版本演进的操作说明离开仓库即腐烂,且 CI 配置改动与手册改动应在同一个 PR 里可见

## 决策

选定**方案 1**:运维手册为**第五类持久文档**,与代码/测试、ADR、CONTEXT.md、复盘、features 目录、原型(ADR-0014)并列。

- **位置(硬性)**:全部放 **`docs/ops/`**,不散在 `docs/` 根目录——与设计文档、复盘同级混放会让下一轮清理再次面临"这份该不该删"的判断;独立目录本身就是分类声明。新增此类文档一律进 `docs/ops/`。
- **判据**:描述"当前流程怎么操作"(命令、配置项、凭据语义、失败判读),而非"当时为什么这么定"或"当时怎么排查出来的"。
- **维护方式**:**就地更新**,不追加不归档——流程变了就改它,与 ADR 的只追加相反。过时的手册比没有手册更有害。
- **与 ADR 的分工**:ADR 记 why(为什么正式版必须公证),手册记 how(公证失败时逐条验证的命令序列)。两者互不替代。

## 后果

- 正面:换机/换证书/重建基础设施时有唯一权威处;清理旧文档时有明确判据,不会误删。
- 负面:多一类需要维护真实性的持久文档;手册与流程脱节时会误导——靠"改流程的 PR 必须同步改手册"兜底。
- 中性:ADR-0013 的四分类扩展为六类(决策/术语/施工/复盘/功能目录/运维手册),原型另见 ADR-0014。
