# ADR-0022:接收文件夹可由用户选定,失效时自动退回默认且不保留原路径

- 状态:已接受
- 日期:2026-08-23
- 相关:[spec](../specs/receive-dir.md) · [features](../features/receive-dir.md)

## 背景

收到的文件一律落系统下载目录,用户无从更改。两条驱动:

1. **产品侧**:下载目录是浏览器的垃圾场,收件混在里面找不到;外置盘/NAS 上的专用收件夹用不上。
2. **合规侧**:Mac App Store 以 Guideline 2.4.5(i) 驳回,两条意见——
   「app 把用户数据存进容器」与「`files.downloads.read-write` 权限似乎没有对应功能」。

第 2 条的事实层经实测澄清:沙盒容器里的 `Downloads` 是**指向真实 `~/Downloads` 的符号链接**,
文件真的落在用户的下载目录,没有埋进容器。**驳回针对的其实是展示给人看的那个路径字符串**——
`app.getPath('downloads')` 在沙盒下返回容器内路径,设置页原样显示,用户在 Finder 里找不到它。

## 决策

### 一、接收文件夹可由用户选定,默认仍是系统下载目录

不做首次启动引导:开箱即用优先。`files.downloads.read-write` 权限因此保留——它是**默认值的依据**,
用途也就说得清了,这同时回应了驳回的第 2 条。

**不为过审删掉这个权限**:删了默认接收目录就写不进去,那是拿功能换过审。

### 二、展示的路径解开符号链接,落盘的路径不解

展示用 `realpath`,于是设置页显示 `/Users/<me>/Downloads` 而非容器路径,回应驳回的第 1 条。
落盘仍用原路径:经符号链接写进去落到的是同一个位置,改落盘路径没有收益,只会在沙盒下多出授权变数。

### 三、目录失效时自动退回默认,且**不保留**原路径

失效包括:目录被删、改名、所在磁盘移除、沙盒授权解析失败——这四种成因在决策层不区分
(解析失败分不清原因,硬分会造出一个测不出来的分支)。

**自动退回**保证文件不会因为一个失效的配置而收不到。**不保留原路径**是取舍的另一半:

- 代价:告知里说不出是哪个文件夹;外置盘拔了再插也不会自动切回,得重选。
- 换来:没有"选了但现在用不了"这种中间态,数据模型只剩"用默认"与"用某个目录"两种。

告知的持久性因此只能靠一个**布尔标记**承载(持久化,活过重启),用户点「知道了」或重新选择时清掉。

### 四、三个操作立即生效,不跟随设置页的「保存」

设置页本就是混合的:自动接收开关与大小上限跟随「保存」,语言与离线设备保留选完即生效。
接收文件夹归后者——选目录是个重量级模态动作,选完还要再点保存,人容易以为已经好了;
而「知道了」是已读回执,点完再被「取消」复活会很怪。

### 五、两条发布线行为一致

Developer ID 版也能选目录。非沙盒不需要 security-scoped bookmark,只多一个平台分支。
行为一致换来的是 features/spec 不用分版本描述、测试不分叉——而用户并不知道自己装的是哪个版本。

## 其他被考虑过的方案

- **首次启动引导用户选一次目录**,从而彻底不需要 downloads 权限。这是 Apple 想要的模式,
  但把开箱即用变成先配置,而绝大多数人会直接选下载目录。
- **只修展示路径,第 2 条驳回靠申诉**。改动最小,但同类申诉(`network.server` 那次)无果。
- **app 自动搬移已有文件**。要处理大文件耗时、中途失败、跨卷复制,且用户可能已在别处引用
  那些文件。改为只提示"旧文件仍在原处"。
- **保留失效前的路径以便目录回来时自动恢复**。更贴心,但引入"选了却用不了"的中间态,
  且接收目录会自己变回去。

## 后果

- 配置新增三项:目录(可空,空即默认)、告知标记、沙盒书签(仅 MAS 版有值)。
  书签与目录在归一化层**强制同生共死**,于是调用方写不出"悬空授权"。
- `AppCore` 的 `receiveDir` 从字符串改为惰性函数——目录可能在两次接收之间失效,
  构造时固化就检测不到。下游 HTTP 层本就是惰性契约,未受影响。
- **一次瞬时探测失败会导致不可逆的退回**(网络卷抖动、外置盘休眠唤醒)。
  这是本决策"不保留原路径"的直接后果,已知且未解决,记在 spec 的边界节。
