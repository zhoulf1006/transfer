# globalShortcut 的能力边界(决定产品只能"提示换键")

> 领域:全局快捷键 · Electron API 能力限制

## 能力边界(三条,来自 API 实际行为)

- `register()` 被别的 app 占用时**静默返回 false**,不抛异常;
- `isRegistered()` **只反映本 app**,探测不到别的 app 的占用;
- OS **禁止互抢**,无法覆盖别 app 已注册的快捷键。

**推论**:冲突检测只能"**注册试错**"——无法预知、无法强占。所以产品上只能在冲突时提示用户换一个键,不存在"自动抢占"或"提前检测冲突"的实现路径。这不是偷懒,是 API 天花板。

## 改键失败必须回滚旧键

**根因**:`rebindShortcut` 的实现是"注销旧 → 注册新"。新键注册失败时若不回滚,用户不但没改成,**连原来能用的截图键也没了**。

## 异步结果被同步清理覆盖

**症状**:改键冲突时,红字提示一闪而过、看不见。

**根因**:录制 UI 的 `onBlur` 无条件清 hint;而冲突提示是 IPC 异步返回后才写进去的,正好被这个同步清理覆盖。

**做法**:仅在 `recording` 态才因失焦清提示。

**通用模式**:"异步结果被同步清理覆盖"——凡是"请求发出 → 期间有同步 UI 重置 → 结果回来写入"的结构都要检查这条时序。
