# 接收文件夹

> 关联: [features](../features/receive-dir.md) · ADR-0022

## Problem Statement

收到的文件一律落系统下载目录,用户无从更改。两类人因此受影响:

- **想把收件归到别处的人**——下载目录本就是浏览器的垃圾场,混在一起找不到;外置盘/NAS 上有专门的收件夹也用不上。
- **Mac App Store 版的用户**:沙盒把 home 重定向进容器,`app.getPath('downloads')` 返回的是
  `~/Library/Containers/<bundle-id>/Data/Downloads` 这样一串容器路径。设置页把它原样显示出来,
  用户在 Finder 里几乎找不到这个位置。App Store 审核据此判定"用户数据被存进 app 容器"(2.4.5(i)),
  并同时质疑 `files.downloads.read-write` 权限"没有对应功能"。

第二条的事实层已实测澄清:容器里的 `Downloads` 是指向真实 `~/Downloads` 的**符号链接**,
文件真的落在用户的下载目录里,没有埋进容器。**问题只在展示给人看的那个路径字符串**。

## Solution

1. **接收文件夹可由用户选定**,默认仍是系统下载目录。选定后的目录立即生效,可随时恢复默认。
2. **展示的路径解开符号链接**,让设置页显示 `/Users/<me>/Downloads` 而不是容器路径。
3. 目录后来不可用时(被删、改名、所在磁盘移除、沙盒授权失效),**自动退回默认目录**并在设置页
   持久告知,直到用户处理。文件因此不会因为一个失效的配置而收不到。

## User Stories

1. As a 收件较多的用户, I want 把接收文件夹指到我自己建的收件夹, so that 收到的东西不和浏览器下载混在一起。
2. As a 用户, I want 改完文件夹后知道"以前收的东西还在老地方", so that 我不会以为文件丢了。
3. As a 用户, I want 随时把接收文件夹改回系统下载目录, so that 我不会被自己的一次选择锁死。
4. As a 用户, I want 选到一个写不进去的文件夹时当场被拦下, so that 失败不会推迟到别人给我发文件的那一刻。
5. As a 用户, I want 我选的文件夹不可用时文件仍能收到, so that 我不在电脑前的时候别人发的东西不会石沉大海。
6. As a 用户, I want 在设置页看到"文件夹已改回默认"的告知且它不会自己消失, so that 我不会因为错过一次提示而长期以为文件在别处。
7. As a Mac App Store 版用户, I want 设置页显示的是我在 Finder 里能找到的路径, so that 我知道去哪儿拿文件。
8. As a 用户, I want 路径太长时看见的是末尾的文件夹名, so that 我一眼认得出是哪个目录。
9. As a 审核人员, I want 这个 app 申请的下载目录权限有肉眼可见的对应功能, so that 我不必按 2.4.5(i) 驳回它。

## 失败模式与边界

### A. 选择文件夹

| # | 情形 | 预期行为 |
|---|---|---|
| A1 | 打开系统选择器后取消 | 什么都不变,不产生"已更改"说明 |
| A2 | 选中一个可写文件夹 | 立即生效;路径行更新;出现「恢复默认」;出现"旧文件仍在原处"说明 |
| A3 | 选中一个**不可写**的文件夹 | 当场拒绝并说明原因,接收文件夹保持原样。用**系统消息框**呈现,不在设置页里加错误态——用户此时刚从模态选择器返回,注意力在对话框那个位置;设置页里的一行红字他多半看不见 |
| A4 | 选中的就是当前正在用的那个 | 视作无变化,不显示"已更改"说明 |
| A5 | 选中的正好是系统下载目录 | 等同于恢复默认——不留自定义记录,「恢复默认」不出现 |
| A6 | 选择器被系统拒绝/异常 | 报错,接收文件夹保持原样 |
| A7 | 选中一个符号链接目录 | 按解析后的真实目录处理,与直接选那个真实目录等价 |
| A8 | 沙盒版选中目录 | 同时保存 security-scoped bookmark;非沙盒版只存路径 |

### B. 恢复默认

| # | 情形 | 预期行为 |
|---|---|---|
| B1 | 自定义状态下点「恢复默认」 | 立即回到系统下载目录;「恢复默认」与说明块一并消失 |
| B2 | 已是默认状态 | 该操作在界面上不存在(不可达),不是禁用态 |

### C. 失效检测与退回

检测在**两个时点**发生:启动时、每次接收文件前。只在启动时查会漏掉"启动后才拔盘"——
人不会为了拔盘先退出 app;只在收文件前查会让设置页长期显示一个早已失效的路径。

| # | 情形 | 预期行为 |
|---|---|---|
| C1 | 启动时目录已不存在 | 退回默认 + 置告知标记 |
| C2 | 启动时目录存在但不可写 | 同 C1 |
| C3 | 启动时目录所在卷已卸载 | 同 C1 |
| C4 | 沙盒下 bookmark 解析失败 | 同 C1。**不区分**"授权失效"与"目录没了"——解析失败分不清原因,硬分会造出一个测不出来的分支 |
| C5 | 收文件前发现目录已失效 | 退回默认 + 置标记,**本次文件仍落默认目录并成功收到** |
| C6 | 检测通过但真正写入时才失败(TOCTOU) | 该次传输按既有失败路径处理;不置告知标记(它不是"配置失效") |
| C7 | 失效退回后目录又变得可用 | **不自动切回**——原路径已不保留 |
| C8 | 重选新目录后新目录又失效 | 标记重新置位,告知重新出现 |
| C9 | 一批文件传输中途目录失效 | 整批沿用开始时确定的落点(见 CONTEXT.md 组批不变量),不中途改道 |
| C10 | **默认目录本身不可用**(用户删了系统下载目录) | 先尝试创建它;创建失败则该次接收按既有失败路径处理。退回默认这条兜底链到此为止——没有第二层兜底,也不静默改落别处 |
| C11 | 自定义目录与默认目录**同时**不可用 | 退回默认后按 C10 处理,即尝试创建默认目录、失败则接收失败。告知标记照常置位 |
| C12 | **瞬时**不可用(网络卷短暂断开、外置盘休眠唤醒的一刹那、权限系统抖动) | **当前行为:与永久失效同等对待——一次探测失败即退回默认,且路径不保留、不可撤销。** 这是「退回即忘」的直接代价:损失的不是一次接收,而是用户的配置本身。已知未解;可选的出路是"连续 N 次失败才判失效"(挡住抖动,代价是多一个计数状态)或"保留原路径以便恢复"(与既定决策冲突,要重开 ADR-0022 的第三条) |

### D. 告知

| # | 情形 | 预期行为 |
|---|---|---|
| D1 | 点「知道了」 | 标记清除,告知消失且不再出现;**不可撤销**(原路径没记,没有"再看一眼") |
| D2 | 不点就关设置页 | 下次打开仍在 |
| D3 | 不点就重启 app | 仍在——标记必须持久化,不能只活在内存里 |
| D4 | 不点,直接选了新文件夹 | 告知一并消失(重新选择即等于已处理) |
| D5 | 告知在时收到文件 | 正常收进默认目录,不因告知未读而阻塞 |

### E. 与既有功能的交互

| # | 情形 | 预期行为 |
|---|---|---|
| E1 | 传输进行中改文件夹 | 进行中的仍落原目录;新目录只对之后发起的传输生效 |
| E2 | 已收到的老消息 | 「打开所在文件夹」仍定位到它当初落盘的位置(消息里存的是绝对路径) |
| E3 | 发送截图用的内部目录 | 不受影响——它不是接收文件夹,也不对用户暴露 |
| E4 | 设置页的「打开文件夹」按钮 | 打开**当前**接收文件夹 |

### F. 路径展示

| # | 情形 | 预期行为 |
|---|---|---|
| F1 | 沙盒下的默认目录 | 显示解开符号链接后的真实路径 |
| F2 | 非沙盒环境 | 解符号链接是空操作,显示不变 |
| F3 | 路径超出可用宽度 | 省略号出现在**左侧**,保留末尾的文件夹名 |
| F4 | 路径以 `/` 开头 | 前导斜杠显示在开头。文本方向为右到左时,`/` 属中性字符会被双向算法重排到末尾——须做方向隔离 |
| F5 | 路径含非 ASCII 字符 | 正常显示,不影响截断位置 |
| F6 | 解符号链接失败 | 退回显示未解析的原始路径,不显示空白 |
| F7 | 路径含换行或控制字符 | 单行显示,不撑破布局 |

### G. 升级与异常配置

| # | 情形 | 预期行为 |
|---|---|---|
| G1 | 从旧版本升级(配置里没有这个字段) | 归一化补默认,行为与全新安装一致 |
| G2 | 配置里的值是垃圾(非字符串、空串、相对路径) | 归一化兜底为默认,不崩溃 |
| G3 | 配置里的告知标记是垃圾值 | 归一化兜底为"无告知" |

## Implementation Decisions

- **配置新增两项**:接收文件夹(可空,空即表示用系统下载目录)与一个**布尔告知标记**。
  沙盒版另需保存该目录的 security-scoped bookmark。
  记住"空=默认"而不是把默认路径写进配置:后者会在系统下载目录变更时留下一个过期的绝对路径。
- **不保留失效前的路径**(用户裁定)。代价是告知里说不出是哪个文件夹,且目录恢复后不能自动切回。
  告知的持久性因此只能靠那个布尔标记承载。
- **决策与探测分离**:目录该用哪个、要不要置标记,由一个**纯函数**根据"配置值 + 默认目录 + 探针结果"
  算出;文件系统探测(存在性、可写性、bookmark 解析)在外层完成。这是本功能的主测试 seam——
  全部失效分支不碰文件系统即可覆盖。
- **展示路径解符号链接**,落盘路径**不解**:经符号链接落到的是同一个位置,改落盘路径没有收益,
  只增加沙盒下的授权变数。解析失败时回退到原始字符串。
- **三个操作立即生效**(更改/恢复默认/知道了),与同页的语言、离线设备保留一致;
  「取消」不回滚它们。同页的自动接收开关与大小上限仍跟随「保存」——这个页面本就是混合的。
- **两条发布线行为一致**。非沙盒版不需要 bookmark,只多一个"是否在沙盒中"的分支。
- **entitlement 不变**:下载目录权限保留(它是默认值的依据),用户选定目录走 user-selected 那条。
- **新增主题变量**一组用于告知块的琥珀色(文字/边框 + 底色)。项目此前只有红色一档,
  而目录失效是需要注意而非出错。主题变量表有四处(系统偏好明暗 + 手动切换明暗),四处都要写。
- **路径展示的方向隔离**:容器保持右到左以让省略号落在左侧,路径文本自成左到右段落。
  整个元素改成左到右不行——省略号会跟着跑到右边,把末尾的文件夹名截掉。

## Testing Decisions

**只测外部行为。** 好测试在这里意味着:不去断言探测函数被调用了几次,而是断言
"给定这样的目录状态,接收文件夹是哪个、告知出不出现"。

三个 seam,按覆盖面从大到小:

1. **接收目录决策(纯函数)**——主 seam。C 组与 A4/A5 的全部分支都在这里覆盖,
   探针结果作为入参传入,不碰真实文件系统,因而能构造"卷已卸载""bookmark 解析失败"这类
   现实中难复现的状态。
2. **配置归一化**——复用既有的配置测试。G 组在这里。
3. **端到端(渲染级)**——只守一条最关键、且只有渲染层才暴露的接线:设置页三个操作**立即生效**
   (改完不点保存也算数)。其余界面细节由原型定形,不重复用 e2e 断言样式。

**缺口(如实记,不造绿)**:

- **沙盒专有路径无法在单元测试里验证**——bookmark 的保存与跨重启解析、容器符号链接的解析,
  都依赖真实沙盒容器。这三条只能在 MAS 构建上人工实测,测试套件里不会有对应的绿。
  实现时须在沙盒构建上逐条走一遍并记录结果。
- A3(不可写文件夹)在 CI 上不稳定——root 权限下"不可写"不成立。纯函数 seam 里以探针结果入参覆盖,
  真实选择器那一层不设自动化断言。

## Out of Scope

- **不搬移已有文件**。改文件夹只影响之后的传输,旧文件留在原处,仅作提示。
  自动搬移要处理大文件耗时、中途失败、跨卷复制、以及用户可能已在别处引用这些文件——代价远超收益。
- **不做"每次接收都问我存哪"**。它把一个配置变成了每次传输的一道门,与自动接收的取向相反。
- **不为失效目录保留路径以便自动恢复**(用户裁定,见 Implementation Decisions)。
- **不改 Developer ID 版的落盘位置**——它不受沙盒约束,当前行为正确。
- **不为过审而删除下载目录权限**:删了默认接收目录就写不进去,是拿功能换过审。
